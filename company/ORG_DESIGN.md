# Kaz Company 組織設計書（v0.2）

Claude Code を「一つの会社」として運営するための組織設計。社長 = Kaz。

---

## 0. 階層の作り方（3層以上を実現する）

**セッションを部署として使う。** Claude Code のクラウドセッションは、別のセッションを作り（`create_session`）、メッセージを送り合える（`send_message`）。親子関係は最大8段まで持てる。各セッションの中では、さらにサブエージェント（社員）を動かせる。

```
第0層  社長（Kaz）……………………… スマホ/PCから本社セッションに話しかける
第1層  副社長 ＝「本社セッション」……… 依頼を受けて、部署セッションに振る
第2層  部長 ＝「部署セッション」………… 部ごとに常設。社員を動かして結果をまとめる
第3層  社員 ＝ サブエージェント ………… 調査・批判・統計など1つの役割に専念
第4層  外注 ＝ Codex（ChatGPT）……… 量の多い下作業を ChatGPT 側の枠で処理
```

| 層 | 実体 | 作り方 |
|---|---|---|
| 副社長 | 本社リポジトリ `kaz-company-hq` を開いたセッション | 全社 `CLAUDE.md` に「振り分け表」と「部署セッションIDの一覧」を書く |
| 部長 | 部署ごとのクラウドセッション（タイトル `[研究企画部長]` など、タグ `dept:research`） | 副社長が `create_session` で作る。職務規程は `company/departments/<部署>.md` |
| 社員 | 部長セッション内のサブエージェント | `.claude/agents/<役割>.md`（役割ごとにモデルも指定） |
| 外注 | `codex exec` | 社員が Bash から呼ぶ |

**依頼の流れ（例：テロメライシンの研究提案）**
1. 社長 →「テロメライシンで臨床研究を考えたい」と本社に言う
2. 副社長 → 研究企画部長セッションに `send_message`
3. 部長 → 調査部・批判的レビュアー・統計担当を並列に起動
4. 部長 → まとめを副社長に `send_message` で報告
5. 副社長 → 社長に要約と「決めてほしいこと」を出す。決定はNotionの決定ログへ

**部署をまたぐ大型案件**（例：CQ一覧から研究テーマを選んで申請書まで）は、Workflow（多エージェント編成）で一気に回す。

     ├─ 治験事務局 ……………………CLIVO試験ほか

## 2. 部署と役割

（担当欄：**C** = Claude、**G** = Codex/ChatGPT に外注。モデル欄は社員サブエージェントの推奨モデル）

### 2-1. 副社長（本社セッション）
- 依頼の受付と振り分け、部署間の連携、決裁待ちの管理、全社の記録
- 秘書室（直轄）

| 役割 | 仕事 | 道具 | モデル |
|---|---|---|---|
| メール係 | 受信の仕分け（要返信／要決裁／参考）、返信の下書き | Gmail | Haiku |
| 予定係 | 予定登録、日程調整案、締切リマインド | Google Calendar | Haiku |
| 朝の報告係 | 当日の予定・未返信・締切・決裁待ちを毎朝まとめる | `morning`、定期実行 | Sonnet |
| 記録係 | 決定事項・議事録・引き継ぎを Notion に残す | Notion | Haiku |

### 2-2. 臨床支援部（日常臨床の相談）
| 役割 | 仕事 | 担当 |
|---|---|---|
| 部長 | 相談の整理（何が問われているか／緊急度）、回答の取りまとめ | C |
| エビデンス調査員 | PubMed・ガイドライン確認。MeSHで検索式→件数で妥当性確認→検索 | C（Sonnet） |
| 薬剤チェック係 | 用量・相互作用・腎機能や肝機能による調整・禁忌 | C（Sonnet） |
| セーフティ係 | 見逃してはいけない疾患、回答の限界の明示 | C（Opus） |
| **CQハンター** | 相談の中から未解決の疑問を拾い、研究企画部の **CQバックログ** に登録 | C（Haiku） |

### 2-3. 治験事務局（CLIVO試験など）
| 役割 | 仕事 | 担当 |
|---|---|---|
| 事務局長 | 試験ごとの進捗と課題の一覧、優先順位づけ | C |
| 文書管理係 | プロトコル・手順書・版管理、改訂差分の要約 | G |
| 登録・進捗係 | 施設ごとの登録状況、目標との差、督促文の下書き | G |
| 安全性・逸脱係 | 重篤な有害事象・逸脱の報告期限と様式の確認 | C（Opus） |
| 規制・倫理係 | 臨床研究法／GCP、倫理審査委員会の提出物チェック | C |
| 会議係 | 議題・資料・議事録、宿題の追跡 | G |
| 問い合わせ対応係 | 施設からの質問への回答案（FAQとして蓄積） | C |

### 2-4. 研究企画部（研究提案＋壁打ち）
| 役割 | 仕事 | 担当 |
|---|---|---|
| 部長（PI補佐） | 問いをPICO/PECOに落とし込み、提案書の骨格を作る | C（Opus） |
| 調査部 | 先行研究、進行中の試験（ClinicalTrials.gov / jRCT）、空白領域 | C＋G（スクリーニングの下読みはG） |
| **批判的レビュアー（上司役）** | 新規性・実現性・倫理・バイアスを突く。**結論を渡さず資料だけ渡す** | C（Opus）＋**G（別モデルの査読）** |
| 生物統計担当 | 主要評価項目、サンプルサイズ、解析計画、多重性 | C（Opus）、計算コードはG |
| 規制・倫理担当 | 臨床研究法の適用、先進医療、同意・利益相反 | C |
| 資金獲得担当 | AMED・科研費・企業共同研究の公募要件との突き合わせ | C |
| 執筆担当 | 計画書・抄録・申請書のたたき台 | G で下書き → C で仕上げ |

- **壁打ちモード**：答えを先に出さず、レビュアーと統計担当が社長に質問を返す
- **CQバックログ**：臨床支援部から上がった疑問をNotionのデータベースで管理する

## 3. 会社の記憶（社外ノート）のしくみ

クラウドセッションは終わると消える。だから、会社の記憶を2か所に分けて置く。**社長が覚える操作は合言葉3つだけ**で、読み書きは社員がやる。

### 3-1. 置き場所は2つ

| 置き場所 | たとえ | 中身 | 社長がやること |
|---|---|---|---|
| **本社リポジトリ**（GitHub `kaz-company-hq`） | 就業規則・組織図 | `CLAUDE.md`（全社ルール）、部署の職務規程、社員の定義、スキル | **何もしない**。セッション開始時にClaudeが自動で読む |
| **Notion「Kaz Company」** | 会社の掲示板と業務日誌 | 下の4ページ | スマホのNotionアプリで眺めるだけ |

### 3-2. Notionに置く4つのページ

| ページ | 何が書かれるか | 誰が書くか |
|---|---|---|
| 📥 決裁箱 | 社長に決めてほしいこと（選択肢＋推奨案） | 副社長 |
| 📒 決定ログ | 日付・部署・決定内容・理由を1行ずつ | 記録係 |
| 🔁 引き継ぎノート | 部署ごとの「今どこまで進んだか／次に何をするか」 | 各部長 |
| 💡 CQバックログ | 臨床で拾った研究の種（重要度・実現性・状態） | CQハンター |

### 3-3. 合言葉（社長が使うのはこれだけ）

| 社長の一言 | Claudeが裏でやること |
|---|---|
| 「**続きから**」 | 該当部署の引き継ぎノートを読んで、前回の続きから再開する |
| 「**記録して**」 | 今日の決定を決定ログに、進捗を引き継ぎノートに書く |
| 「**決裁箱**」 | 決裁待ちの一覧を出す。社長が「1はA、2は保留」と答えれば反映する |

さらに全社 `CLAUDE.md` に「セッションを終える前には必ず引き継ぎノートを更新する」と書いておけば、「記録して」と言い忘れても残る。

### 3-4. セッション間のやりとり
- **リアルタイム**：`send_message`（副社長 ⇄ 部長）。部長セッションは常設なので、前回の文脈を覚えたまま次の依頼を受けられる
- **非同期**：Notionの引き継ぎノート（部長セッションが作り直されても続きから再開できる）
- **定期実行**：秘書室の朝の報告は「スケジュールされたタスク」で毎朝自動実行

## 4. トークン節約：ChatGPT（Codex）との分業

### 4-1. 方針
**判断はClaude、量はChatGPT。** Codex CLIはChatGPTアカウントでログインするので、Claudeの利用枠ではなくChatGPTのプラン枠を使う。

| ChatGPT（Codex）に回す | Claudeに残す |
|---|---|
| 文献スクリーニングの一次読み、表への転記 | 研究の問い、採否の判断 |
| 議事録・督促文・定型文書の下書き | 社長に出す最終版 |
| 英文の一次校閲、翻訳の下訳 | 医学的な正確さの確認 |
| 統計解析のコード作成 | 解析計画の設計 |
| 一括の書式整え、ファイル変換 | 品質保証（引用・数値の確認） |

### 4-2. もう一つの利点：別のモデルによる査読
批判的レビュアーは、Claudeの査読とChatGPTの査読を**両方**取る。同じモデル同士だと見落としが重なりやすいため、異なるモデルを使うと上司役として強くなる。

### 4-3. Claude内部の節約
- 社員ごとにモデルを指定する。定型作業はHaiku、調査・下書きはSonnet、判断と批判だけOpus
- 部長セッションは常設して使い回す（毎回ゼロから説明し直すコストを省く）
- 社員には「結論だけ返す」よう職務規程に書く（部長の文脈を汚さない）

### 4-4. 呼び出し方
社員サブエージェントの定義に次の手順を書いておく。
```bash
codex exec "（具体的な作業指示）" > result.md
```
ChatGPTから返ってきたものは、必ずClaude（部長か品質保証室）が確認してから上に上げる。

## 6. 運営ルール（承認・守秘）

最後に決める（保留）。叩き台：外部送信・削除・予定の確定・金銭は社長の承認制／患者・被験者の識別情報は入力しない／独立レビュー／出典必須／決定ログ。
